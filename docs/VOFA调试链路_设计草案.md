## 0. 一句话

**下位机把「四路实际速度 + 四路目标速度」按帧推给 VOFA+ 画曲线；VOFA+ 用滑块/命令发文本命令回来，改 kp/ki、改目标、单路或四路、启停。**

## 1. 你要的四件事，对应到实现

| 你的需求 | 实现 |
|---|---|
| 看四路实际速度 + 目标速度 | 上行 8 通道：`v1..v4`（实测）+ `t1..t4`（目标），单位 mm/s |
| 滑块调 kp / ki | 下行命令 `KP1 0.15` / `KI1 0.05`，VOFA 滑块绑命令 |
| 滑块调目标转速 | 下行命令 `T1 150`（单路）或 `TA 150`（四路同值） |
| 命令控制单路 / 四路 / 启停 | 下行命令 `START` / `STOP` / `M1 150` / `MALL 150` |

**现有代码已经准备好的接口**（`task.h`，本轮已实现）：

```c
void  Task_MotorControl_SetTarget(uint8_t motor_id, float target_mm_s);  // 1~4
float Task_MotorControl_GetTarget(uint8_t motor_id);
float Task_MotorControl_GetActual(uint8_t motor_id);
void  Task_MotorControl_Start(void);
void  Task_MotorControl_Stop(void);
```

所以下一步只是「组帧 + 收命令 + 解析」，**不用再动速度环本身**。

⚠ 还缺一个能力：**kp/ki 在线改**。现在 `p/i/d` 是 `Motor` 结构体里的初值，没有运行时入口。需要新增 `Task_MotorControl_SetGain(id, kp, ki, kd)`，并在 `motor.c` 里让 PID 用最新增益。

## 2. 链路长什么样

```
                 ┌──────────── PC ────────────┐
                 │  VOFA+                     │
                 │  波形控件 ← 8 通道         │
                 │  滑动条 ──► 命令（文本）   │
                 └───────┬───────────┬────────┘
                 USB-TTL │           │ USB-TTL
                         ▼           ▼
                    TX  ──────────────►  STM32
                    RX  ◄──────────────  STM32
```

- **上行（STM32 → PC）**：定时推帧，50~100 Hz。
- **下行（PC → STM32）**：不定时，来一条解析一条，**必须放在中断/空闲回调里收，不能轮询堵主循环**。

---

## 3. 上行协议：【待定】二选一

| | FireWater（文本） | JustFloat（二进制） |
|---|---|---|
| 帧格式 | `任意前缀:ch0,ch1,...,chN\n` | N 个 float32（小端）+ `00 00 80 7F` |
| 8 通道一帧 | ≈ 66 字节（`%.1f`） | 36 字节 |
| 115200 下 100 Hz 占用 | **≈ 57%** | ≈ 31% |
| CPU 开销 | 高（浮点转字符串） | 低（直接内存字节） |
| 串口助手能直接看懂 | 能 | 不能（乱码） |

**我的建议：先用 FireWater。** 理由：调试阶段你需要在串口助手里肉眼对数值，FireWater 一眼就能看出「第 3 路是不是反了」；8 通道 50 Hz 只占 29% 带宽，够用。等链路稳了、要提频再换 JustFloat。

> 依据：VOFA+ 官方文档（`vofa.plus/docs`）与多篇第三方教程一致；帧尾 `00 00 80 7F` 是 IEEE754 的 +∞。**官方说 FireWater 适合「通道不多、频率不高」——8 通道 × 100 Hz 已经接近它的舒适区上限。**

## 4. 下行命令格式（建议，等你确认）

文本命令，一行一条，`\r\n` 结尾，大小写不敏感：

| 命令 | 含义 | 例 |
|---|---|---|
| `START` / `STOP` | 四轮使能 / 刹车 | `START` |
| `M<id> <mm/s>` | 单路目标 | `M1 150` |
| `MALL <mm/s>` | 四路同值 | `MALL 150` |
| `K<id> <kp> <ki> <kd>` | 单路增益 | `K1 0.15 0.05 0` |
| `KALL <kp> <ki> <kd>` | 四路同增益 | `KALL 0.15 0.05 0` |
| `RATE <hz>` | 上行帧率 | `RATE 50` |

**为什么用文本而不是二进制命令**：VOFA+ 的「命令 / 滑动条」控件发字符串最省事，你以后自己加一条命令不用重编固件；而且下行数据量极小（几十字节/秒），带宽不是问题。

## 5. 走哪个串口：【待定】三选一

| 方案 | 引脚 | 优点 | 代价 |
|---|---|---|---|
| **A. USART2** | PA2/PA3 | 已有 `printf`，一个 USB-TTL 就够，接线不变 | 调试文字和波形数据混一条线；`printf` 是阻塞发送，必须先改成缓冲/DMA |
| **B. UART5** | PC12/PD2 | 干净独立，`printf` 留着打文本；波形线专心跑帧 | 要第二个 USB-TTL；**PC12/PD2 是否引到排针 =【未知】，得看板子** |
| C. USART1 | PA9/PA10 | — | **不可行**：视觉 DMA + IDLE 已占用 |

**我的建议：A（USART2）先跑通，之后再考虑 B。** 理由：你现在只有一个 USB-TTL 的概率大；而且 `printf` 的阻塞问题本来就要修（顺手一起改成 DMA 发送），修完两条用途共用一条线也不冲突——前提是**波形帧和调试文本不要同一时刻都发**，所以建议把 `printf` 降级为「只在出错时打」。

---

## 6. 必须先解决的三个技术问题

1. **`printf` 阻塞**：`fputc` 逐字节 `HAL_UART_Transmit(..., HAL_MAX_DELAY)`。8 通道 100 Hz 会被它拖死。→ 改成环形缓冲 + `HAL_UART_Transmit_DMA`，满了丢帧不阻塞。
2. **接收不能轮询**：USART2 现在没有 RX 中断/DMA。→ 照抄 USART1 的做法（DMA + IDLE + FIFO），但**命令是变长的文本，用不上定长帧**，建议 IDLE 中断 + 行缓冲，遇 `\n` 解析一条。
3. **浮点打印开销**：FireWater 用 `vsnprintf` + `%.1f`，在 168 MHz 上 66 字节的格式化约几十微秒，50 Hz 可接受；100 Hz 时要注意别在中断里做。

## 7. 实施步骤（每一步都能单独验收）

| 步 | 内容 | 验收 |
|---|---|---|
| 1 | `usart.c` 的 printf 改成环形缓冲 + DMA；串口助手里文本不乱、不掉 | 连打 1 万字符不卡主循环 |
| 2 | 新增 `vofa.c/h`：8 通道 FireWater 组帧，50 Hz 推送 | VOFA+ 里看到 8 条曲线，数值和串口助手一致 |
| 3 | USART2 加 IDLE 收命令，实现 `START`/`STOP`/`M1`/`MALL` | VOFA 命令面板点一下，轮子启停 |
| 4 | 实现 `K<id>` 改增益（需新增 `SetGain` 接口）+ `RATE` | 在线改 kp，曲线立刻变化 |
| 5 | 角度环接进来，加 `yaw` 与 `yaw_target` 两通道 | 角度环也能在线看/调 |

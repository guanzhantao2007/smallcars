三、踩到的三个坑（都不报在源码行上，最难查）0
坑 1：undefined reference to atan2f / sqrtf
我把 -lc -lm 写进了 target_link_options，CMake 把它生成到 对象文件前面。链接器是从左往右解析的，走到 .obj 发现需要 atan2f 时，库早就处理完了 → 找不到。
正解：库要用 target_link_libraries(m)，这样才会排在对象文件后面。
坑 2：objcopy: .../´úÂë¿â/smallcars£¨renxun first/... No such file
工程路径含中文（代码库、（renxun first）。objcopy 经 cmd.exe 传绝对路径时被转成 GBK，变成乱码，文件当然找不到。
正解：后处理命令改用相对文件名 + WORKING_DIRECTORY，不传任何中文绝对路径。
发现 3：cmake / ninja 原本都没装
这台机器只有 GCC 和 mingw32-make。已用 pip install cmake ninja 装进 WorkBuddy 的 Python 环境（cmake 4.4.5 / ninja 1.13.2）。那个环境若被重置，重装一次即可。
